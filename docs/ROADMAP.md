# خطة التنفيذ وقائمة المهام

ليست تقدير مواعيد أو تكلفة. الترتيب حسب الاعتماديات ومعايير الخروج، لا حسب وعود زمنية.

## M0 — تجربة التفاعل (منفذة)

- [x] إدخال 5 مقاسات والتحقق منها.
- [x] إعادة بناء جسم من مكتبة مفتوحة.
- [x] عباية توضيحية قابلة للتغيير، front/side/orbit.
- [x] واجهة RTL وألوان الهوية، خط مضمّن.
- [x] ملف مستقل، صفر طلبات شبكة، JSON محلي.
- [x] اختبارات هندسية وتفاعل متصفح على مقاسين للشاشة.
- [ ] مراجعة صاحب المشروع للتجربة. **قرار: تعديل الرحلة أم تثبيتها؟**
- [ ] إنشاء/رفع المستودع الخاص؛ محجوب حاليًا بصلاحيات الاتصال.

## M1 — حسم محرك الجسم (بوابة إنتاج أولى)

- [ ] تدقيق مصدر أصول/بيانات body-model وتراخيصها.
- [ ] تعريف القياسات مع الورشة: مسار الكتف، محيط الصدر، الوسط والأرداف، الطول والحذاء.
- [ ] حساب قياسات هندسية مستقلة من شبكة الجسم، لا قراءة معاملات الإدخال.
- [ ] مقارنة body-model مع Anny+clad-body على نفس مصفوفة المدخلات.
- [ ] اختبار نسب مختلفة، لا الحد الأدنى والأقصى معًا فقط.
- [ ] تثبيت حدود الأخطاء المقبولة ومجال المدخلات مع الورشة، لا اختراع tolerance.
- [ ] تثبيت محرك وإصدارات وأصول ومعيار تحويل وحدات.

الخروج: سجل اختلافات مقاس بمقاس، ترخيص مسموح وواضح، وحدود منتج منشورة. لو فشل، نغيّر المحرك أو نسميه عرضًا تقريبيًا فقط.

## M2 — رقمنة قطعة مكة واحدة

- [ ] توفير باترون مملوك للمشروع مع خطوط الخياطة والسماحات والكم والفتحات.
- [ ] فصل body measurements عن finished garment measurements وease.
- [ ] تحديد الباترون المغلق/المفتوح والطبقة الداخلية.
- [ ] إعداد mesh seams وUV وخامة واحدة مصوّرة بإضاءة ثابتة.
- [ ] قياس/ضبط خواص الخامة للمحاكاة، لا تخمينها من اللون.
- [ ] تجربة Blender؛ استخدام GarmentCode لتوليد الباترون فقط إذا وفّر مجهودًا.
- [ ] مطابقة التصميم من الأمام والجانب والخلف مع القطعة الفعلية.

الخروج: قطعة رقمية معتمدة يدويًا، مصدر وترخيص وإصدار معروف، لا مجرد شكل شبيه.

## M3 — إثبات drape والملاءمة

- [ ] حل body collisions وself collisions والخياطة والاستقرار.
- [ ] سيناريوهات حقيقية للطول والصدر والأرداف والكتف، ومصفوفة طول/كم/وسع.
- [ ] صور مقارنة لعينات منفذة على قياسات متفق عليها بموافقة صاحباتها.
- [ ] تمييز شكل الخامة عن اتجاه المقاس/الشد؛ لا heatmap غير مقاس.
- [ ] فحص إضافات حقوق الخامات والباترونات وأي solver.

الخروج: تقرير نجاح/فشل بصري وهندسي، وتحديد ما يمكن وعد العميلة به.

## M4 — تغليف تجربة المتجر

- [ ] معرفة المنصة وتحديد embedding/route مستقل.
- [ ] Widget لا يعطل الشراء العادي، يفتح اختياريًا.
- [ ] ربط معرف المنتج/اللون وتعديلات الورشة الفعلية.
- [ ] cache لا يحتوي معرفًا شخصيًا، ومفتاح إصدار للباترون/الخامة.
- [ ] اختبارات Android وiOS وأجهزة متوسطة حقيقية، بطارية/ذاكرة/WebGL fallback.
- [ ] سياسة بيانات وموافقة صريحة إذا أضيف حفظ/إرسال.
- [ ] CSP وحدود ملفات/حماية API إن وُجد backend.

## M5 — تجربة مغلقة قبل إطلاق

- [ ] اختبار مع عميلات متطوعات وبموافقتهن.
- [ ] أسئلة فهم: هل اعتقدتِ أن الصورة ضمان؟ هل الخطوات واضحة؟
- [ ] تسجيل أخطاء وملاحظات بدون مقاسات أو صور في logs العامة.
- [ ] قياس تكملة الرحلة والطلب مقارنة بخط أساس؛ لا وعود تحويل بلا بيانات.
- [ ] قناة رجوع للتجربة العادية وإيقاف الميزة إذا كانت مضللة.

## نموذج issue

عنوان + المكوّن + خطوات إعادة الإنتاج + المتوقع + الفعلي + جهاز/متصفح + نسخة الملف + قيم تجريبية غير شخصية + معيار الإغلاق. أي تغيير محرك أو خامة أو باترون يعيد الاختبارات المتأثرة.
